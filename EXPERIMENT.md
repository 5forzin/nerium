# Initial interception experiment

Date: 2026-10-24.

## Environment

- Windows host with WHPX acceleration.
- Android Emulator 37.2.12.0; Google APIs Android 14 x86_64 image, API 34, revision 14.
- Magisk 27.0 and Vector 2.2, build 3080, framework API 102.
- Device Probe and Device Lab Module 0.1.0 debug APKs.
- Independent detector: reveny Android-Emulator-Detection v1.5.0 release APK, package `com.reveny.emulator.detection.sample`.

The module scope included only Device Probe and the independent detector. The Android system framework and System UI were not selected.

## Interpretation

Process-scoped Java identity interception works on this setup. It does not make this emulator indistinguishable from physical hardware. No Play Integrity, hardware attestation or third-party service acceptance was tested.

Raw JSON observations and fresh independent-detector UI dumps are in the local `reports/` directory. They are excluded from version control. Use `scripts/compare_reports.py` to compare the framework-only and enabled reports.

## Setup notes

The lab used [rootAVD](https://github.com/newbit1/rootAVD) at commit `c8638d0ee386017d9f1a0ed5247bb6f0749bbcff`. The emulator was stopped after testing. Its configured image, installed applications and module scope remain available for the next run.

## Private namespaces and ARM64 execution, version 0.3

The probe now has 33 checks. Two additions exercise inline CPU and ordinary-file reads, using an actual x86_64 `syscall` or ARM64 `svc #0` instruction. Disassembly confirmed both instruction paths; the old `syscall()` wrapper path remains as a separate check. All six I/O controls must pass, and unavailable results are never counted as clear.

Java hooks now cover the reference fingerprint, declared ABI lists and sensor labels. Sensor events are unchanged. A shared native property profile also supports inherited subprocesses. The Zygisk component creates a private mount namespace for each of the two scoped app processes and uses a root companion to mount filtered CPU information and cloned property areas. Magisk `resetprop -n` runs after entering this namespace and modifies only cloned areas. Inherited read-only property mappings are then replaced at the same virtual addresses after specialization. This last step covers the translated ARM libc, which bypasses the original x86 libc hooks.

The final CPU mount uses the 201-byte generic ARM CPU reference captured from the stock native bridge, rather than retaining the Intel description with one flag removed. The libc fallback captures its CPU view after process specialization. All five CPU read paths are checked for identical full text as an additional validation outside the 33 checks. The reference is an emulated CPU description and does not reproduce Tensor G3 hardware.

The first CPU mount failed because SELinux rejected associating the `proc_cpuinfo` label with a data-filesystem file. The final implementation uses `system_file` and leaves SELinux enforcing. A later property-mount-only test still produced eight ARM native findings: new subprocesses saw the profile, but inherited mappings saw original properties. Remapping those inherited pages removed those findings. These intermediate results remain in the local reports.

The probe APK contains both x86_64 and ARM64 libraries built from the same source. The architecture function and its detection condition were not modified. ## Version 0.8: openat2 availability
